========================================
03 / Outcome 项目目标（6 个月 / 2000 字内）
========================================

一、项目定义

Replay 是一个「录屏复刻」社区。一个用户只需上传自己的操作录屏，我们的 agent 就能完成意图理解与步骤拆分，自动生成结构化工作流；其他用户则可用自己的 agent 工具，结合各自的差异化环境（不同机器/分辨率/账号/软件版本），一键复刻这段录屏操作。

类别：桌面 GUI 自动化 + AI Agent + 工作流分享社区（C 端）。
核心对象：工作流（workflow）= agent 从一段用户录屏中理解、拆分出的可复用结构化操作序列。

主流程分四阶段：
1）上传录屏：用户提交自己的操作录屏（键鼠事件与逐步截图），这是用户唯一要做的事。
2）意图理解与步骤拆分：我们的 agent 用多模态大模型理解用户意图，过滤误操作、把零散动作拆分或合并为任务级步骤、抽取可变参数（如收件人、搜索词）、生成自然语言步骤描述，产出结构化工作流。
3）跨环境复刻：其他用户用自己的 agent 工具执行该工作流，用 SMC（序贯蒙特卡洛）视觉与语义定位对齐目标元素，不依赖硬编码坐标，结合各自差异化环境实现跨机器、跨分辨率、跨用户的一键复刻。
4）社区分享：工作流导出为带 sha256 校验、防篡改、含隐私审查标记与跨平台兼容信息的可移植包，在社区上传、下载、复用。

差异化能力：
跨用户复现——A 用户上传的录屏工作流，B 用户结合自身差异化环境可直接一键复刻。
速度——三层加速已实现：截图解析 LRU 缓存、lookahead 预测式流水线（后台提前解析后续若干步）、确定性动作快路径（跳过截图与大模型调用）。
安全——复现可随时中断，含输入围栏、卡键释放、键盘隔离，避免自动化失控。

现状：上述能力已在可运行原型中打通，含完整代码结构、安全机制与单元测试。

二、6 个月目标状态

从「可运行原型」推进到「一小群真实用户每日使用、并已开始互相分享工作流」的早期产品，跑通「上传录屏→意图理解与步骤拆分→跨环境复刻→社区复用」完整闭环。

三、成败判据（可量化）

复现能力：站内 20 至 30 个高频场景端到端复现成功率达到 80% 以上。
跨环境：换分辨率、换机器、界面小改版后目标仍能对齐，主要场景通过。
速度：单步复现延迟明显低于同类方案。
社区飞轮：关注种子工作流数、被复用工作流数、人均复用次数、以及是否出现非种子用户的自发贡献，出现正向增长与自发贡献即达标。
留存：种子用户周留存与自然推荐，出现「每日使用、离不开」的人群。
高频场景示例：素材批量整理、跨平台内容搬运、批量改表、下载归档、重复填单。

四、阶段决策规则

继续加码：跨环境复现成功率与延迟达标，且出现真实自发复用，且有明确留存人群。
重新定义：复现能力达标但社区无法转动，则收缩为个人自动化工具，先做深单机价值。
关停：长尾场景复现成功率长期无法突破可用线，判定技术路径当前不成立。

五、已完成（证明非纸面 idea）

端到端可运行系统已具备：录制（键鼠与截图）、大模型理解（过滤、合并、抽参、描述）、SMC 跨环境复现、三层加速、可移植社区打包格式、可中断安全机制、单元测试。6 个月的工作，是把它从「能跑」推进到「有真实用户每日使用并开始分享」。
